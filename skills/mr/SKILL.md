# YouTube to Suno MR

Turn a YouTube URL into a Suno-hosted rehearsal accompaniment: acquire audio, remove vocals locally, upload the resulting MP3 through Suno MCP, and create an instrumental cover from that uploaded MP3. Report the uploaded source and every generated candidate. A separated vocal-free track can still contain instrumental melody: the actor needs a backing with no foreground or doubled vocal tune.

Use the user's language. Defaults from this workflow: MP3 for uploads and delivery, a piano-led introduction, instrumental accompaniment without guide melody or solos, original timing and harmony as closely as possible, audio influence 100%, weirdness 0%, and style influence 10%. Explicit user choices override these defaults. Do not extend a source-specific tempo, key, intro length, or genre to another song.

## Prerequisite: Suno MCP

Discover the live Suno MCP tools and verify the connection before downloading or processing audio. Look for account/usage, audio upload, retrieve, cover creation and wait capabilities; use the tools' current schemas rather than inventing endpoints or parameters. Check the authenticated plan and credits when available. The tool names vary by host.

If Suno MCP is missing, disconnected or unauthenticated, explain the following setup and the missing connection; do not claim Suno tasks succeeded. Follow the host's own OAuth approval flow and resume the user's request once connected:

- **Codex:** `codex mcp add suno --url https://api.suno.com/mcp` then `codex mcp login suno`.
- **Claude Code:** `claude mcp add --transport http suno https://api.suno.com/mcp`, then run `/mcp` in a session and sign in.
- **Claude app or other MCP clients:** add `https://api.suno.com/mcp` as a custom connector and authorize the Suno account. A local shell/filesystem is also needed for the helper below.
- Follow [Suno's current MCP setup guide](https://help.suno.com/en/articles/14551425). If the server is already registered, do not add it again. Guide installation rather than silently modifying another client's configuration.

## Pipeline

1. **Acquire.** Take the supplied YouTube URL as the input; no manual audio upload is needed. Use `yt-dlp` with `--no-playlist` and `bestaudio`, placing the download in a new task workspace. Inspect with `ffprobe`, and check any known Suno plan duration limit before expensive separation; do not silently crop a long source. If the user explicitly supplies a local file or an already uploaded instrumental instead, use that input and skip only the unnecessary steps. Local lossless/intermediate audio may be used internally; user-facing audio files and Suno uploads default to MP3. Respect applicable source and Suno usage rights.
2. **Separate.** Prefer a suitable installed stem separator. The included [helper](scripts/make_mr.py) is a tested local fallback using Demucs and FFmpeg. Resolve `<skill-dir>` to the directory containing this `SKILL.md` and run `python <skill-dir>/scripts/make_mr.py INPUT --output NEW_OUTPUT.mp3`; the output must not already exist. Set `TORCH_HOME` to a writable task workspace or temporary directory before running, so first-use model downloads do not depend on home-directory writes. Install required tools into an isolated environment if missing: Python 3.10/3.11 with `yt-dlp`, `demucs==4.0.1`, compatible `torch`/`torchaudio`, `numpy<2`, `scipy` and `soundfile`, plus `ffmpeg`/`ffprobe`. First use may download model weights and CPU processing can take minutes. The helper subtracts an estimated vocal from the source and preserves its timeline; inspect residual voice, humming and accompaniment loss. It does not remove an instrumental melody by itself.
3. **Analyze before prompting.** Use measured duration and real audio evidence to describe pulse, meter, intro/entry cues, quiet spaces, transitions, dynamics and ending. Where available, use Suno's timing/lyrics analysis on an already accessible clip or local signal analysis. Clearly label automatic estimates and uncertainty; ASR gaps can contain dialogue or wordless vocals. Do not invent exact chords or infer instrumental melody absence from tags or silence. Prefer the separated MP3 as the reference, rather than the vocal-containing original.
4. **Upload the MP3.** Call the discovered audio-upload session tool; send the MP3 bytes to its one-file upload URL, complete that session, and retrieve/poll the clip until `complete` or `error`. HTTP PUT 200 and `submitted` are not completion. Once complete, run the available Suno audio-analysis tool on the uploaded MP3 and incorporate its beat and section estimates into the prompt, clearly marked as estimates. Its instrumental tags cannot reveal missing original vocal-entry cues; preserve those only when supported by local analysis or an already accessible source. Treat signed upload URLs as credentials and never put them in public files or messages. Reuse an existing completed source when appropriate. If a rights/content restriction is returned, report the exact failure and stop. Do not alter audio, metadata or access paths to defeat that restriction. If the user separately requested another format for size/compatibility, or documented evidence supports a technical format issue, one ordinary test of that format is reasonable; if it is also rejected, stop and report. Never present a format change as a way to evade content checks.
5. **Create the MR in Suno.** Unless the user requested upload only, cover the completed **vocal-separated MP3**. Use the observed source structure, a piano intro and accompaniment-only roles: piano chords, bass and rhythm, leaving the sung/foreground melody to the performer. Keep the rest of the original arrangement and transitions as close as possible. Exclude voices, humming, guide melody, solo lead and new fills. With the current MCP, omitting both lyrics and voice ID requests an instrumental; follow the actual tool schema if it changes. Use an integer duration only if supported, and a unique idempotency key for the generation. If advanced controls are unavailable, report that the requested values could not be set rather than pretending they were applied. Audio influence 100% is not a bit-exact lock.
6. **Verify and deliver.** A creation can return multiple clip IDs: wait for every ID using the generation wait tool and return every successful Suno link, duration, and the local MP3. Keep the prompt and settings reviewable. Compare the source and output durations and available section/timing data. Listen or use an actual audio-listening model for the complete track before claiming voice, guide melody, piano intro, or fidelity are verified. If no listening method is available, label these unverified; metadata, a 100% setting, tempo/key matches, and an instrumental tag do not prove musical identity or absence of a melody. If a download tool returns `requires_credit`, follow its confirmation requirements.

## Failure boundaries

- Detect missing `yt-dlp`, FFmpeg, Python dependencies or unavailable models and state the actual missing dependency; no global installation is required. Record evidence of installation or separation failures.
- Keep each experiment bounded. Do not repeatedly submit unchanged failed uploads, silently switch source audio, create additional paid generations without task authorization, or conflate a service moderation error with proof of legal infringement.
- If the user reports drift, compare the specific cause. Whole-song covers can rewrite the arrangement even at 100% influence; favor the source-derived backing or supported section editing. Do not promise perfect source retention from generated audio.
- Keep copyrighted audio, generated media, OAuth tokens, upload URLs and user-specific clip IDs out of the public skill repository.
